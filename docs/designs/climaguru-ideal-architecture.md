## Problem Statement

ClimaGuru es un servicio para consultar APIs de clima con capa gratuita (OpenWeather, Meteosource, Open-Meteo, SIATA, SAB), comparar esos datos con lecturas de sensores IoT, guardar consultas por usuario, y ver mapas con radares (SIATA Medellín, SAB Bogotá, IDEAM). El frontend permite consultas públicas sin auth, y tras el login los usuarios pueden agregar API Keys y ver su historial de consulta. Todo se despliega en una VM con conectividad Tailscale entre equipos, con seguridad verificada y formatos de salida unificados (JSON, CSV, YAML, texto) listos para ciencia de datos posterior.

## What Makes This Cool

Comparar datos de sensores IoT con APIs de clima públicas en un mismo lugar, con mapas de radar de múltiples fuentes (SIATA para Medellín, SAB para Bogotá, IDEAM para coordenadas de consuladas/radares activos) y la capacidad de interpretar todos los formatos de salida para aplicar ciencia de datos después.

## Constraints

- Las consultas de clima deben usar APIs con capa gratuita únicamente.
- El frontend permite consultas sin autenticación para APIs públicas; el login es solo para agregar API Keys y guardar historial.
- Despliegue en máquina virtual, equipos conectados por VPN Tailscale.
- Seguridad del sitio verificada (auditoría).
- Todos los formatos de salida (JSON, CSV, YAML, texto) deben integrarse e interpretarse para ciencia de datos posterior.
- El desarrollo actual es local; los cambios se suben a GitHub y se hace pull en el server.

## Premises

1. Clima gratuito + sensores IoT — ClimaGuru consultará APIs de clima con capa gratuita y posteriormente comparará esos datos con lecturas de sensores IoT. **ACEPTADA.**
2. Frontend sin auth para consultas públicas — Vista pre-login para consultas que no requieran autenticación; post-login se agregan API Keys y se guarda historial. **ACEPTADA (con ajuste del usuario).**
3. Mapas con radares — SIATA Medellín, SAB Bogotá, y otro mapa con coordenadas de consuladas y radares IDEAM activos o histórico disponible. **ACEPTADA (con ajuste del usuario).**
4. Usuarios + API Keys + registros — Login con posibilidad de agregar API Keys y ver registros de consulta, manteniendo la capacidad de hacer consultas simples sin autenticarse. **ACEPTADA (con ajuste del usuario).**
5. Despliegue en VM + Tailscale — Ya desplegado; se trabajará local y se subirá a GitHub para pull en el server. **ACEPTADA (con ajuste del usuario).**
6. Verificación de seguridad — Auditoría de seguridad del sitio. **ACEPTADA.**
7. Formatos de salida + ciencia de datos — Integración de JSON, CSV, YAML, texto para interpretación y ciencia de datos posterior. **ACEPTADA.**

## Approaches Considered

### Approach A: Minimal viable

Frontend React simple con consultas públicas sin auth (mapas, radares, SIATA Medellín, SAB Bogotá). Backend Flask ligero con login, API Keys y historial de consultas. Consumo de APIs gratuitas básicas. Despliegue push a GitHub → pull en server. Sin ciencia de datos todavía.
- Esfuerzo: S · Riesgo: Low
- Rechazado: demasiado limitado para el alcance que el usuario describió (no cubre IDEAM, ciencia de datos, seguridad auditada).

### Approach B: Ideal architecture (ELEGIDO)

Backend Flask con arquitectura limpia (services, adapters, modelos existentes en el repo). Autenticación JWT + API Keys por usuario + historial de consultas persistido. Mapas con radar SIATA, SAB, IDEAM. Frontend con vistas públicas pre-login y vistas autenticadas post-login. Formatos de salida unificados con data processor para interpretación. Seguridad auditada (OWASP). Despliegue en VM + Tailscale listo para producción.
- Esfuerzo: L · Riesgo: Med

### Approach C: Science de datos primero

Enfoque en ciencia de datos desde el día 1: unificación de todos los formatos, data processor avanzado, interpretación automática de consultas. Comparador sensores-IoT vs APIs desde el inicio.
- Esfuerzo: L · Riesgo: High
- Rechazado: la ciencia de datos es posterior a este desarrollo; el IoT es posterior también.

## Recommended Approach

**Approach B — Ideal architecture.** Ya tienen el despliegue en VM, necesitan seguridad verificada y quieren algo completo que puedan usar en otros proyectos IoT después. Cubre todos los requisitos sin sobre-ingeniería prematura.
